# CarBoyZ — Reconstructed State

Generated by a full read of every file in `src/` plus `npm test` / coverage results. 476/476 tests passing. This replaces guesswork from journal titles with ground truth from the code.

**Entry point:** `src/index.js` → `src/core/index.js` re-exports the public domain surface (config, services, `VendorAdapter`, `Dealer`/`Vehicle`, `seedInventory`). The actual browser app boots from `src/ui/App.js`'s `mountApp()`, wired to `document.getElementById('app-root')` on `DOMContentLoaded`. A separate Node process, `src/server/index.js` (`npm run start:server`), runs a Hono HTTP + `ws` WebSocket relay for cross-device sync — independent of the static PWA bundle.

## 5. Server (`src/server/`) — implemented, thin

- `index.js` (92%/92%): Hono app with tenant resolution (route param → query → header → subdomain) and a `/api/v1/health` + `/api/v1/tenants/:id` stub endpoint. `startServer()` boots `@hono/node-server` + the ws relay together.
- `wsRelay.js` (96%/91%): Tenant-scoped WebSocket rooms; relays only `SUBMISSION_CREATED`/`POLICY_UPDATED` message types verbatim to other clients in the same tenant room. No persistence, no auth, no message validation beyond type/tenantId match.

This is the entire backend. There is no database, no REST CRUD beyond the two stub routes above, and no policy-mutation persistence server-side — `SpreadConfigService` writes to the browser's own `localStorage`, not through this server.

## Summary: what's real vs. what the roadmap doc assumed

**Confirmed fully implemented, tested, integrated** (contradicts nothing in `docs/REBUILD_ANALYSIS.md`'s "Completed Capabilities" list):
- PWA/white-label multi-tenant canvas, branding, manifest generation
- MapLibre + CARTO Dark Matter map, GPS locate, ZIP/city search w/ Google+OSM+offline fallback, procedural dealer scatter
- VendorAdapter feed ingestion, VIN scanning w/ real check-digit validation, chat-based buyer search (regex + optional LLM)
- SyncAdapter cross-tab/cross-device sync (BroadcastChannel + WebSocket relay)
- **Spread/pricing policy engine** — already exists (`SpreadService` + `SpreadConfigService` + `DispatchService`), contrary to the roadmap listing it as an MVP gap to build

**Confirmed gaps** (the roadmap's "Needed for MVP" list holds up):
- No isolated per-tenant backend container/runtime — `src/server/` is a single shared Hono+ws process with two stub routes and no persistence.
- No QR phone-to-desktop *physical* handoff — `SessionStashService`/`SyncAdapter` solve same-tenant state sync, but there's no session-stash-to-QR-code wiring found in the UI (the QR encoder is used for buyer-search deep links and appraisal-sheet verification, not session handoff).
- No offline service worker / Workbox queue — no `sw.js` or service-worker registration exists anywhere in `src/`.
- No policy mutation ledger/versioning/audit log — `SpreadConfigService.saveConfig()` overwrites localStorage with no history, no diff, no hash, no userId/timestamp trail.
- No analytics version-pinning or what-if simulation engine — `AnalyticsService` computes point-in-time metrics only; no replay/counterfactual capability exists.

**Test/coverage posture:** 476 tests, all passing, 91% branch coverage overall. Coverage gap is concentrated entirely in DOM-mounting view functions (App.js, MapView.js, the *View.js files) — a consistent, intentional pattern, not scattered incompleteness. Every domain model, service, and adapter meets or nearly meets the CLAUDE.md 80% bar; the UI view layer does not, by design (thin DOM glue over tested controllers/logic).
